# 23 Uploading Records from Upload Tables (adapter upload framework)
- External data loaded into upload tables (macro Excel or other utility; ODT does not populate them), then upload routine invoked from screen **CVDUPLOD** per function id. Same flow as gateway/UI for consistency. Supports maintenance and transaction screens.
- Flow: insert into upload tables -> trigger on master upload table inserts process-table row (status `U` unprocessed, function id) -> CVDUPLOD invokes routine -> cursor over unprocessed rows -> adapter converts upload types to base types and calls function main package -> process table updated (status, error code...).
- Components: process table, upload tables, trigger on master upload table, adapter package, CVDUPLOD wrapper calling adapter by function id.
- Naming (recommended for new tables): 4th letter of base table becomes U (STTM_CUSTOMER -> STTU_CUSTOMER); consulting/client tables `<table>_U_EXTGBL`.
- Process tables: **CSTB_EXT_CONTRACT_STAT** (transactions; key EXTERNAL_REF_NO + EXTERNAL_SEQ_NO + BRANCH_CODE + SOURCE; updated EXPORT_STATUS, CONTRACT_REF_NO, ERR_CODE, ERR_MESSAGE; also IMPORT_STATUS, POST_IMPORT_STATUS, ACTION_CODE, FUNCTION_ID, MODULE, PRODUCT_CODE, COUNTERPARTY, USER_ID, JOBNO, UPLOAD_ID = thread) and **STTB_UPLOAD_MASTER** (maintenance; key MAINTENANCE_SEQ_NO + SOURCE_SEQ_NO + BRANCH_CODE + SOURCE_CODE; UPLOAD_STATUS updated; MAINTENANCE_TYPE, UPLOAD_INITIATION_DATE, USER_ID, ACTION_CODE, UPLOAD_ID = thread).
- Upload table guidelines: master data source always mapped (master upload table; except some call forms); only NORMAL data sources; several strictly 1:1 data sources may share one upload table; if master DS is shared (CSTB_CONTRACT) group it with a child (e.g. CSTB_CONTRACT + FXTB_CONTRACT_MASTER -> FXTB_UPLOAD_MASTER) so master upload table is unique per function; keep same column names; exclude internal/invisible columns.
  - Standard columns: SOURCE_CODE, SOURCE_REF (contracts) / MAINTENANCE_SEQ_NO (maintenance), SOURCE_SEQ_NO, BRANCH_CODE (composite PK; detail tables add own unique id); optional in master: FUNCTION_ID (needed when parent+child share table), ACTION_CODE (absent = NEW only), UPLOAD_ID (multithreading), UPLOAD_STATUS (when upload table = master table, e.g. PC contract), MODULE, SOURCE_OPERATION (else derived from action code).
  - Transactions: EXTERNAL_REF_NO must map to a base column (usually CSTB_CONTRACT) to resolve ref on modify. Same upload table for unrelated data sources (e.g. buy/sell legs as aliases) via Upload Table Where Clause (on upload columns). Call form master DS that is a view (e.g. CSTBS_CONTRACT__ADV) gets no upload table.
- Triggers: no ACTION_CODE column -> process ACTION_CODE = NEW; parent+child share trigger via FUNCTION_ID; no triggers for call forms.
- Adapter package `<module>pks_<fid>_ext_upload` (e.g. `fxpks_fxfdtronl_ext_upload`): types = transaction adapter (cursor on CSTB_EXT_CONTRACT_STAT, handles SUBSYSSTAT), maintenance adapter (STTB_UPLOAD_MASTER), transaction call form adapter (called from txn adapter, updates SUBSYSSTAT), maintenance call form adapter.
- ODT config: data source Upload Table (no synonyms; button shows standard columns, renamable e.g. SOURCE_REF -> EXT_REF_NO), Upload Table Where Clause, per-column Upload Table Column, Not Required in Upload Table. Generates adapter package, upload trigger, upload table DDL (+ separate drop script; ignore DDL if reusing tables). Upload config is refresh-safe (customizations retained, kernel mappings merged); regenerate all after refresh.
- Append-only uploads (e.g. floating rates) are NOT supported by default (multi-record blocks require full data; missing rows deleted). Handle by SOURCE_OPERATION in custom package: skip system functions and write own upload, or merge existing rows into the screen object early (preferably in pre_check_mandatory).
