# 04 Screen Development I (core design reference)
- ODT generates: front-end JS (SYS js), UIXML, PL/SQL packages, static data scripts, XSDs, Excel templates, HTML. Developer adds only business logic in release-type-specific units (KERNEL / CLUSTER / CUSTOM layering, non-invasive).
- radxml naming: `<FUNCTIONID>_RAD.xml` (e.g. `FTDTRONL_RAD.xml`). Changes are segregated per release inside the radxml.
- **Design steps**: 1 data sources & relations, 2 data blocks, 3 screen layout, 4 field sets, 5 call/launch forms, 6 LOVs, 7 summary, 8 actions. Save often.
- **Header**: Action (New/Load); Function Id (max 8 chars; chars 1-2 = module; 3rd char D=detail, R=report, C=call form, N=notification; summary uses S, gateway G e.g. `FTDTRONL`, `FTSTRONL`, `FTGTRONL`); Save Xml Path; Function Type (Parent / Child = inherits, can modify / Screen Child = layout-only); Parent Function; Parent Xml; Function Category (Maintenance, Transaction, Report [BI Publisher], Summary, Others [all logic hand-written]); Header Template (None / Process = workflow: Workflow Ref, Priority); Footer Template (None / Maint Audit / Maint Process / Process).
  - Maint Audit column to block field (reserved names): MAKER_ID=MAKER, MAKER_DT_STAMP=MAKERSTAMP, CHECKER_ID=CHECKER, CHECKER_DT_STAMP=CHECKERSTAMP, MOD_NO=MODNO, RECORD_STAT=RECSTAT, ONCE_AUTH=ONCEAUTH, AUTH_STAT=AUTHSTAT. Template adds them automatically; never add manually.
- **Preferences** drive static scripts for SMTB_MENU, SMTB_FUNCTION_DESCRIPTION, SMTB_ROLE_DETAIL, SMTB_FCC_FCJ_MAPPING: Module (LOV from SMTB_MODULE; first 2 chars of generated package names), HO Function (HO_FUNCTION; other branches query-only), Logging Required (LOGGING_REQD; logs to CSTB_MSG_LOG for View Change), Auto Authorization (AUTO_AUTH; needs function+user+branch level), Tank Modification (TANK_MODIFICATIONS; maintenance only; untanked in EOD), Field Log Reqd (FIELD_LOG_REQD; STTB_FIELD_LOG/STTB_RECORD_LOG), Excel Export Required, Multi Branch Access (MULTIBRANCH_ACCESS + Txn Block Name/Txn Field Name of branch code, emitted in SYS js), Branch Program ID, Process Code (workflow), SVN Repository Url. Menu grid: one row per related function id (Main Menu, Sub-Menu1, Sub-Menu2). Control String (CONTROL_STRING, also SMTB_ROLE_DETAIL): allowed operations; REVERSE/ROLLOVER/CONFIRM/LIQUIDATE/HOLD only for transaction screens; disabled for summary.
- **Data Sources**: LOV of business-schema objects; alias gives `TABLE__ALIAS`. Props: Master (exactly one; cannot be multi-record), Relation Type (1:1 / 1:N), Multi Record, PK Cols / PK Types (`~`-separated, e.g. `CONTRACT_REF_NO~VERSION_NO` / `VARCHAR2~NUMBER`; defaulted from STTB_PK_COLS), Parent, Relation (parent on left, only equality with parent, no third table; e.g. `STTM_CUSTOMER.CUSTOMER_NO=STTM_CUST_ACCOUNT.CUSTOMER_NO AND ...`), Where Clause (no WHERE keyword; goes into `fn_sys_query` of main package), Default Order By (no ORDER BY keyword), Type (Normal / Query = no DML / InOnly = in request not response, no DML / Summary = ignored by packages), Mandatory, Upload Table (+ per column Upload Table Column, Not Required in Upload Table). Column Max Length is overridable here (drives field max length).
  - Rules: tables/views have 5th char `_`, no double underscores; synonyms add `S` before first `_` (ACTB_DAILY_LOG to ACTBS_DAILY_LOG). Never use a view as NORMAL type (generates inserts on view). 1:N child needs at least one more PK col than parent. Parent above children in tree.
- **Global release rule**: any element (data source, column, block, field, screen, tab, section, field set, LOV, custom attribute, screen arg, call/launch form) can be deleted or renamed ONLY in the release that created it. In later releases use Visible / Active flags instead. Regenerate all units after delete/rename/reorder.
- **Data Blocks**: name `BLK_...`, must NOT contain the table name (block names are exposed in request/response XML). Props: Block Title (label; matters for multi-record), Parent, XSD Node (default = name minus BLK_, `_` to `-`, sentence case), XSD Annotation, Multi Record, Block PK fields (`~`; used for change log), Relation Type, Master Block (exactly one), Block Type (Control = UI only, only UI fields / Normal / Summary). A multi-record data source attaches to only one block; several data sources in one block only if strictly 1:1 and always co-existing (else dummy rows are inserted). A single-record DS may be in many blocks; each column maps to one field. Data sources added in one release cannot be removed later.
- **Block Fields**: from data source columns (names/labels defaulted from CSTB_DATA_DICTIONARY) or UI fields (not in request/response). Field name must differ from column name and avoid `_` (CONTRACT_REF_NO to CONTREFNO). Label code format `LBL_<XSDTAG>` in CSTB_LABELS.
  - Display types: Amount (Related Block + Related Field = currency field placed above), Button (Events), Checkbox (attrs ON/OFF mapped to e.g. Y/N), Date, Date Time, File, Label, LOV, Mask (Mask Id from STTB_FIELD_MASK), Password, Radio, Read Only Select, Restricted Text (no special chars), Text (default), Text Area (rows/cols; >100 chars), Select.
  - Item Type: DATABASE (from data source; only these appear in packages and SYS js), CONTROL (buttons/labels), DESC (description display; needs Parent Field with LOV whose return field it is; preferred over Query data sources; that LOV must not bind control items).
  - Other props: Min Val / Max Val (validation generated front+back), Max Decimals, LOV Name / Offline LOV Name (branch offline mode), Field Size, Default Value (front-end only), Preview Value, Popup Edit Reqd, Required (asterisk), Visible, Input by LOV Only, Calendar Text, Upper Case Only, LOV Validation Reqd (server-side), Not Reqd in XSD, Report Parameter, Read Only, Custom Attributes (name = label code, value = stored value, Active, Position), Exact Fetch, Hot Key Required, Focus Required.
  - Button Events: Event Name (usually onclick), Function Name (JS, only for NORMAL/SUBFUNCTION), Event Type = Call form / Launch form / Sub screen / OBIEE / Normal (must be placed in a field set) / Sub Function (process flow); Button Screen, Call Form Name, Screen Name.
- **Screens**: name `CVS_...`. Props: Screen Title, Main Screen (exactly one; only it launches from FLEXCUBE; others via buttons), Visible, OBIEE (needs title + button label), Screen Size (small/medium/large), Exit Button Type (Default Cancel / Default OK Cancel / Default Ok Reject Cancel), Screen Arguments (Arg Name, Source Block/Field or hard Arg Value e.g. EXECUTEQUERY, Target Block/Field, Active).
  - Portions Header/Body/Footer with default tabs TAB_HEADER, TAB_MAIN, TAB_FOOTER (never delete). New tabs `TAB_...`; Tab Type Data or Service (embedded call form, branch screens) + Dependent Fields. Footer cannot have multiple tabs. Single-tab screen: only TAB_MAIN, no sections in TAB_HEADER. Footer template means TAB_FOOTER needs no manual design.
  - Sections `SEC_...` (every tab needs one; Collapse, Visible, Multiple Section = multi-entry blocks only). Partitions: large screen body/header max 3, large footer max 4, medium/small max 2 (sub-partitions count). Width defaults evenly.
  - Visibility cascade: hiding screen/tab/section hides children and their field sets; re-showing does NOT re-show children.
- **Field Sets** `FST_...`: Label, Data Block (fixed after release), Multi Record (derived), View Type (Single with navigation / Multiple grid), Height, No of rows (default 15), Type (Normal / Image Set / Version = block must have VERNO, LASTVERNO), Screen/Portion/Tab/Section/Partition, Horizontal, Read Only (hides +/- only), Navigation Button, Visible; field order and sub-partition per field. A field may be in only one visible field set.
- **LOVs**: Global (CSTB_LOV_INFO, function id COMMON) vs local. Name `LOV_...`. Query uses `?` binds (e.g. `SELECT CUSTOMER_TYPE FROM STTM_CUSTOMER WHERE CUSTOMER_NO=?`). Populate columns: Data Type, Visible, Reduction Fld (+ type TEXT/CHECKBOX/RADIO/SELECT), Redn/Col Label (required), Is Mandatory + Min Search Char Length (min 3). Attaching: Bind Variables (block, field, data type, in query order; "Default from LOV Definition"), Return Fields (query col to block field). Generates CSTB_LOV_INFO script. Avoid inline views and ORDER BY.
- **Call Forms** (3rd char C; cannot launch standalone; subsystems e.g. settlement, tax): Function Id, Parent Data Block, Relation Type (1:1 only), Call Form Screen, Display Type (Button / Tab [branch only]), Active, Screen Arguments (Populate from CSTB_CALL_FORM_NODES), Dependent On (fields + other services, to re-default the subsystem). Maintenance call forms only on maintenance screens; transaction ones only on transaction screens. Compile the call form's CSTB_CALL_FORM_NODES + SMTB_MENU scripts before attaching.
- **Launch Forms** (view-only, independently launchable, e.g. accounting entries): Function Id, Active, Screen Arguments; CSTB_CALL_FORM_NODES row must be inserted MANUALLY; pass ACTION_CODE=EXECUTEQUERY plus PK values. Launched by button with event type Launch form.
- **Actions**: XSD Type Identifier (e.g. `LCProd`), Service Name (LOV from GWTM_OPERATIONS_MASTER), Operation Id (sentence case, unique in service; QUERY + `Product` = `QueryProduct`), Action Codes (maintenance: QUERY, NEW, MODIFY, AUTHORIZE, DELETE, CLOSE, REOPEN, SUMMARYQUERY; transactions all), Operation Code (overridable by double-click), Action Stage Type (multistage). Amendable per action and block: All Records, New Allowed, Delete Allowed, Mandatory (XSD minOccurs). Required for web services.
- **Summary**: Title, Data Block (a single-record block or a summary-type block), Data Source, Summary Type (Summary / Query [defunct] / Bulk Authorization / Upload), Size, Default Where, Default Order By, Multi Branch Where, Main Summary Screen (dashboards), Summary Web Services Required (needs SUMMARYQUERY action), result fields + Query fields (max 12, with LOV properties), field ordering, Custom Buttons (max 5 rows; label + JS function in release JS). Maintenance: summary and master block PK field names must match.
- Appendix: Screen Preview (double-click field to navigate), Locate Field, Label Code Maintenance (LBL_ codes, Insert/Update + Deploy to CSTB_LABELS in env language; Fetch Missing Labels; Fetch All Labels), tree Search, Undo.
